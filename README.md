# 문제 발굴소

고민 하나를 적고, 한 층씩 파 내려가며 문제를 뾰족하게 만드는 연습장이에요. 단계마다 내 생각을 먼저 쓰면 AI가 근거와 빈틈을 짚어 줍니다. AI는 답을 대신 써 주지 않고, 점수와 되물음만 줍니다.

## 단계

| 층 | 단계 | 쓰는 것 |
|---|---|---|
| 1 | 문제 쓰기 | 무슨 일, 누가, 언제·어디서, 손해 |
| 2 | 5 Whys | 줄마다 "확인됨 / 추측 / 확인 필요"를 표시. 근거가 없으면 멈추고 확인할 질문을 남김 |
| 3 | 이슈 트리 | 나누는 기준과 가지 2~6개 (MECE 점검) |
| 4 | 가설과 반례 | 먼저 확인할 후보, 가설, 틀렸다면 보일 것, 작은 확인 방법 |
| 5 | 5 Hows (선택) | 오늘 할 첫 행동까지 구체화 |
| 6 | SCQA (선택) | 상황·문제·질문·제안 네 문장 |
| 종합 | 종합 점검 | 단계별 점수 모아 보기, 전체 흐름 점검, 내용 복사 |

## 실행

빌드 도구는 없어요. 정적 파일이라 폴더를 서버로 띄우면 됩니다.

```bash
python -m http.server 8765
# 브라우저에서 http://localhost:8765/index.html
```

`index.html`을 바로 열어도 동작하도록 `import` 없는 일반 스크립트로 만들었어요.

### AI 평가는 Claude 아티팩트 안에서만 동작해요

"AI 평가 받기"는 Claude 아티팩트가 제공하는 `sample` 기능(`window.claude.use('sample')`)을 써요. 아티팩트가 아닌 곳에서 열면 이 기능이 없어서, 평가 버튼을 누르면 "이 화면에서는 AI 평가를 쓸 수 없어요"라고 나와요. 직접 쓰는 연습, 스스로 점검, 종합 화면은 그대로 쓸 수 있어요.

아티팩트로 올릴 때는 `capabilities: {"sample": {}}`를 선언하고, `index.html`, `styles.css`, `js/*.js`를 함께 올려요.

## 파일 구성

```
index.html        뼈대(마크업)와 스크립트 불러오기
styles.css        "발굴 현장" 테마. 맨 위 :root에 색·글꼴 토큰
js/state.js       단계 정의, 상태(S), 저장, 공용 도우미
js/views.js       단계별 입력 화면, 종합 화면
js/evaluate.js    평가 기준(RUBRIC), AI 프롬프트, 평가 결과 카드
js/checks.js      AI에 보내기 전 스스로 점검
js/app.js         화면 그리기, 이벤트, 시작
```

각 파일은 `window.PL`에 필요한 것을 올리고 서로 가져다 써요. 불러오는 순서는 `state → views → evaluate → checks → app`이에요. `import`를 쓰지 않는 일반 스크립트라서 로컬 서버 없이도 로드돼요.

## 고쳐 쓰기

- **평가 기준 바꾸기:** `js/evaluate.js`의 `RUBRIC`에서 단계별 관점을 고쳐요. 프롬프트 규칙(점수 기준, 말투)도 같은 파일의 `evaluate()` 안에 있어요.
- **스스로 점검 바꾸기:** `js/checks.js`의 `localChecks()`에서 단계별 조건을 고쳐요.
- **단계 추가:** `js/state.js`의 `STEPS`와 `blank()`, `js/views.js`의 화면 함수, `js/evaluate.js`의 `RUBRIC`·`describe`·`hasContent`, `styles.css`의 지층 색(`.l1`~`.l7`)을 함께 고쳐요.
- **디자인 바꾸기:** `styles.css` 맨 위 `:root`의 색과 글꼴 토큰만 바꾸면 돼요. 라이트가 기본이고, 다크는 `data-theme="dark"`일 때만 적용돼요.

## 저장

작성 중인 내용은 이 브라우저의 `localStorage`(`problem-lab-v1`)에만 저장돼요. 다른 기기나 다른 사람에게는 가지 않아요. 맨 위 "새 문제로 시작"으로 지울 수 있어요.

## 바탕이 된 개념

5 Whys, 이슈 트리·MECE, 가설과 반례, 5 Hows, SCQA. 5 Whys는 다섯 번을 반드시 채우는 방식이 아니에요. 근거가 없으면 "확인 필요"로 멈추고 다음에 확인할 질문을 남겨요.
